# 公开开发集离线 token 前缀诊断

只复用既有七组开发响应；未调用检索、embedding、Answer、Judge 或正式评测。报告是证据召回代理，不是回答准确率或官方成绩。

官网声明 Answer 可用 117,760 输入 token，包含问题、选项、指令。公开模型配置未披露 production Answer 标识；主分析使用官方 tiktoken 的 `o200k_base`（假设 GPT-4o 家族），另以 `cl100k_base` 检查敏感性。不能声称已精确匹配官方模型或提示词。

默认预留未知指令 2,048 token 和聊天格式 64 token，问题与选项按公开原文实际编码另扣；并列 512、8,192 指令预留作敏感性分析。候选代理格式为 `Memory {rank}:` 标签与完整返回正文，原有 source/邻接包装均计入；保留整条排序前缀，超出时停止，不截断正文、不跳选。117,760 一档扣除了上述非证据开销，不是给记忆独占整个输入窗口。

## 选择含义

这批响应在两种编码下的全文最大值为 71,001 token。三档未知指令预留下，输入窗口代理上限最多使 0 道题删除后续条目。因而这批数据的官方大窗口推断主要受检索质量和下游噪声影响，较小字符预算表不能直接代表窗口上限。

在主分析的 16k token 下，等权 E5 仍退步；32k token 时它在 LoCoMo 获得 3 题、未丢失完整覆盖，LongMemEval All 持平但 Macro 提高；64k 及更大预算时，它在两个小子集的 All 均提高。等权 E5 值得进入更大固定开发集的比较；这些少量得失仍不足以确认最终方法或回答正确率。0.5 权重没有显示稳定优于等权。

## 敏感性与适用范围

本次预算网格中，两种编码造成 All/Macro 变化的聚合单元数为 0，不同指令预留造成变化的单元数为 0。这支持当前小集预算结论对这些假设稳定，不证明未知官方 prompt 一定相同。

完整 JSON 保存两种编码、三档未知指令预留和各 token 预算的聚合指标与配对得失，且记录源文件/原始响应哈希。API 错误仍计入请求分母；指标按完整来源正文 v2 重新计算，session 命中不代替证据 turn。

token 和字符不是同一个单位。这里不能恢复服务此前因 250,000 字符总上限或 16,000 字符邻接窗口排除的来源；也无法衡量大量无关证据对回答模型的干扰。单个 LoCoMo 会话的题目相关、LongMemEval 仅 20 题；需要在更大的固定公开开发分组中检验候选，再作独立验证。
